# Plan 01-01: Centralized SQL Stored Procedure for Unified Aadhaar Deduplication

## Purpose
Create and deploy a single centralized database stored procedure `dbo.usp_REC_ValidateAadhaarCard` that unifies Aadhaar verification across Active Employees (`SAL_Employee_Mst`), Active Candidates (`REC_Candidate_Applications`), and Talent Bench records. Update `dbo.usp_REC_SubmitVendorCandidate` to check against active employees and talent bench.

## Proposed Changes

### Database Stored Procedure 1: `dbo.usp_REC_ValidateAadhaarCard`
- Accepts:
  - `@AadhaarNo NVARCHAR(50)`
  - `@CompanyId VARCHAR(100) = NULL`
  - `@CurrentAppId BIGINT = NULL` (for excluding self during dossier updates)
- Logic:
  1. Sanitize Aadhaar string (strip spaces, hyphens, dots).
  2. Validate 12-digit format.
  3. **Check 1: Blacklisted & Active Employees (`SAL_Employee_Mst`):**
     - If `isBlacklisted = 1`: Return `IsDuplicate = 1`, `CanProceed = 0`, `DuplicateType = 'BLACKLISTED'`, with message.
     - If active employee (`(resignation_date IS NULL OR resignation_date > GETDATE()) AND ISNULL(is_active, 1) = 1`): Return `IsDuplicate = 1`, `CanProceed = 0`, `DuplicateType = 'EMPLOYEE'`, with employee code, name, designation.
  4. **Check 2: Active ATS Pipeline Candidates (`REC_Candidate_Applications`):**
     - Match `AadhaarNo` where `(@CurrentAppId IS NULL OR pk_appId <> @CurrentAppId)`.
     - If in active stage / interview: Return `IsDuplicate = 1`, `CanProceed = 0`, `DuplicateType = 'ACTIVE_PIPELINE'`, with candidate name, MRF, vendor, current stage.
     - If in Talent Bench (`MrfCode = 'BENCH'` or `Stage = 'Bench'` or `IsRejected = 1`): Return `IsDuplicate = 1`, `CanProceed = 1`, `DuplicateType = 'TALENT_BENCH'`, with candidate name, AppId, and allocation recommendation.
  5. **Check 3: All Clear:**
     - Return `IsDuplicate = 0`, `CanProceed = 1`, `DuplicateType = 'NONE'`, message = 'Aadhaar is unique and clear.'

### Database Stored Procedure 2: `dbo.usp_REC_SubmitVendorCandidate`
- Update existing procedure to invoke or mirror `usp_REC_ValidateAadhaarCard`:
  - Prevent duplicate vendor submissions if candidate is an active employee in `SAL_Employee_Mst`.

## Verification Plan
- Execute test script against SQL Server testing:
  1. Test with unique 12-digit Aadhaar $\rightarrow$ Returns `CanProceed = 1, IsDuplicate = 0`.
  2. Test with Aadhaar matching active employee $\rightarrow$ Returns `CanProceed = 0, DuplicateType = 'EMPLOYEE'`.
  3. Test with Aadhaar matching active candidate $\rightarrow$ Returns `CanProceed = 0, DuplicateType = 'ACTIVE_PIPELINE'`.
  4. Test with Aadhaar matching currentAppId $\rightarrow$ Returns `CanProceed = 1` (self-exclusion passes).
