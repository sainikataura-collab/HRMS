# Plan 02-01: Sourcing Surfaces Deduplication & Document Submission Stage Progression

## Context
Candidates and staffing vendors input Aadhaar numbers across Manpower Public Apply, Vendor Add Candidate batch rosters, and Candidate Dossier / Document Submission.
Currently:
1. Public Apply calls legacy procedure that misses active employees.
2. Vendor registration only checks duplicates within the current client-side table array and does not query the database in real time.
3. When vendors/candidates submit documents and complete statutory dossiers, the candidate stays stuck in the "Selected" stage instead of advancing to "Docs_Submitted" (Site HR verification queue).
4. Saving dossiers did not cross-verify Aadhaar against existing employees or other active candidates.

## Objectives
1. Expose `verifyAadhaarUniqueness` in `AtsService`.
2. Connect `PublicWalkinApplyComponent` to `verifyAadhaarUniqueness`, showing real-time feedback and blocking submission for active employees and active pipeline duplicates.
3. Add real-time debounced Aadhaar duplicate checking on batch candidate rows in `VendorAddCandidateComponent` and `VendorPortalComponent`, with visual validation badges and pre-flight batch blocking.
4. Update `dbo.usp_REC_SaveCandidateOnboardingDossier` to validate Aadhaar uniqueness against active employees and active pipeline candidates, and support automatic progression from `Selected` to `Docs_Submitted`.
5. In `VendorPassedInterviewComponent` and `VendorPortalComponent`, when submitting candidate documents / dossier, advance the candidate to `Docs_Submitted`, update UI state, and refresh lists so the candidate moves to the next step cleanly.
