# Plan 03-01: Candidate Hire Deduplication, Clean UI Labels & Robust Employee Code Generation

## Context
When recruiters hire candidates and transfer them to the Employee Master in `CandidatePipelineComponent`:
1. The modal UI exposes raw database tables and SQL functions (`Today (GETDATE())`, `Generated from SAL_Company_Config (e.g. T000011)`, `Required for SAL_EmployeeOther_Details`).
2. There is no duplicate Aadhaar verification in the Hire modal or in `confirmHireAndTransfer()`. If an Aadhaar belongs to an existing active employee or another active candidate, it does not show any warning and sends the payload anyway.
3. In `dbo.usp_REC_HireAndTransferToEmployeeMaster`, there is no duplicate check against `dbo.SAL_Employee_Mst` or active candidates prior to inserting.
4. In `dbo.usp_REC_HireAndTransferToEmployeeMaster`, the employee code sequence defaults to `0` and generates `EMP000001` (or `EMP-001`) in all cases because of company ID prefix mismatches (`'8'` vs `'GU-8'`), NULL prefixes, and failure to inspect existing employee codes in `dbo.SAL_Employee_Mst` (where company `GU-8` already has active codes up to `313046`).

## Objectives
1. Remove all SQL function and DB table internal names from `candidate-pipeline.component.html` and replace with human-friendly, professional HR labels.
2. Add real-time Aadhaar duplicate validation to the Candidate Hire modal in `candidate-pipeline.component.ts` and `.html` (with checking spinners, verified badges, and duplicate warnings).
3. In `confirmHireAndTransfer()`, block submission if Aadhaar is a duplicate.
4. Update `dbo.usp_REC_HireAndTransferToEmployeeMaster` in SQL Server to:
   - Normalize `@CompanyId` (handling both `'GU-'` prefixed and plain numeric IDs).
   - Validate `@AadhaarNo` using `dbo.usp_REC_ValidateAadhaarCard` and reject duplicates before inserting into `SAL_Employee_Mst`.
   - Implement intelligent sequence generation: if `SAL_Company_Config.maxEmpcode` is 0 or null, inspect existing `dbo.SAL_Employee_Mst.empcode` for that company to start at the actual next sequential number.
   - Increment and persist `maxEmpcode` in `dbo.SAL_Company_Config` under a transactional lock.

### Task 2: Real-time Aadhaar Deduplication in Candidate Pipeline Hire Modal
- In `Frontend/src/app/pages/all-dashboard/recruitment/candidate-pipeline/candidate-pipeline.component.ts`:
  - Add state variables: `hireAadhaarStatus: 'idle' | 'checking' | 'verified' | 'duplicate' = 'idle'`, `hireAadhaarMessage: string = ''`, `hireAadhaarDuplicateDetails: any = null`.
  - Add method `onHireAadhaarInput()`: cleans non-digits, and if 12 digits, debounces and calls `atsService.verifyAadhaarUniqueness(cleanAadhaar, this.hireForm.appId)`.
  - When opening the modal in `hireCandidate(candidate)`, if candidate has a 12-digit Aadhaar, immediately run `onHireAadhaarInput()`.
  - In `confirmHireAndTransfer()`: if `this.hireAadhaarStatus === 'duplicate'`, abort and display `toastr.error('Cannot hire candidate with duplicate Aadhaar number.', 'Duplicate Aadhaar')`.
- In `Frontend/src/app/pages/all-dashboard/recruitment/candidate-pipeline/candidate-pipeline.component.html`:
  - Update Section 3 Aadhaar input with `(input)="onHireAadhaarInput()"`.
  - Add status badge (`Checking...`, `Verified`, `Duplicate`) and error alert below the input showing `hireAadhaarMessage`.
  - Disable "Confirm Hire & Transfer" button if `hireAadhaarStatus === 'duplicate' || hireAadhaarStatus === 'checking'`.

### Task 3: Server-Side Duplicate Check & Sequence Generation in SQL Stored Procedure
- In `dbo.usp_REC_HireAndTransferToEmployeeMaster`:
  - Add call to `dbo.usp_REC_ValidateAadhaarCard` on `@AadhaarNo` passing `@AppId`.
  - If duplicate is found (active employee or other active candidate), return `Success = 0` with the specific message and abort.
  - Normalize `@CompanyId`: `@CleanCompanyId = REPLACE(@CompanyId, 'GU-', '')`, `@PrefixedCompanyId = 'GU-' + @CleanCompanyId`.
  - Check `dbo.SAL_Company_Config` matching `pk_companyId IN (@CompanyId, @CleanCompanyId, @PrefixedCompanyId)`.
  - If `maxEmpcode` is 0 or null, dynamically inspect `dbo.SAL_Employee_Mst` for `@CompanyId`:
    - For numeric codes (e.g. `GU-8`), `SELECT @MaxCode = ISNULL(MAX(TRY_CAST(empcode AS BIGINT)), 0) FROM dbo.SAL_Employee_Mst WHERE fk_companyId IN (...)`.
    - If `@Prefix` is non-empty and empcode starts with `@Prefix`, find `MAX(TRY_CAST(SUBSTRING(empcode, LEN(@Prefix)+1, 20) AS BIGINT))`.
  - Increment `@MaxCode = @MaxCode + 1`.
  - Ensure uniqueness with `WHILE EXISTS ...` loop.
  - Update `dbo.SAL_Company_Config SET maxEmpcode = @MaxCode WHERE pk_companyId IN (...)`.

## Verification Criteria
1. Hire modal in candidate pipeline displays clean labels without any DB table or SQL function names.
2. Typing a duplicate Aadhaar in the Hire modal shows a real-time red duplicate badge and blocks "Confirm Hire & Transfer".
3. Attempting to hire a candidate with an active employee's Aadhaar fails with a clean server-side error message.
4. Transferring a candidate to Employee Master generates the correct sequential employee code (e.g. `313047` for `GU-8`) instead of `EMP000001`.
5. No build commands (`dotnet build`, `ng build`) are executed; dev servers remain stable.
